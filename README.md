# 130 UNICEF клуб — вэбсайт

130-р сургуулийн **130 UNICEF клуб**-ын албан ёсны вэбсайт (2025 онд байгуулагдсан). Сургууль
дотор болон гадна хүүхдүүдэд туслах, хүүхдийн эрхийг сурталчлах клубын мэдээ, арга хэмжээ, гишүүд,
зургийн цомог, гишүүнчлэлийн өргөдөл болон админ хэсэгтэй.

**Production:** https://unicef-club-130.erkhes-labs.workers.dev (нэвтрэх: «Нэвтрэх» товч, админ: `/admin`)

- Нийтийн сайт: Монгол (үндсэн) + Англи (`/en`), цайвар/бараан горим, гар утсанд зориулсан.
- Админ хэсэг (`/admin`): мэдээ, арга хэмжээ, гишүүд, цомог, өргөдөл, зурвас, тохиргоо, хэрэглэгчид.

## Локал дээр ажиллуулах

Шаардлага: [Bun](https://bun.sh) ≥ 1.3. Cloudflare бүртгэл **шаардлагагүй** (D1/R2-ийг локалд
дуурайлгана).

```bash
bun install
cp .dev.vars.example .dev.vars
# .dev.vars дотор Clerk Development instance-ийн 2 түлхүүрийг өөрөө бичнэ (доорх «Clerk тохиргоо»)

bun run db:migrate:local        # локал D1 хүснэгтүүд
bun run db:seed:local           # жишээ контент (заавал биш)

bun run dev                     # http://localhost:3000  → «Нэвтрэх»
bun run admin:grant -- <таны-и-мэйл> --dev   # нэг удаа нэвтэрсний дараа өөрийгөө админ болгох
```

Cloudflare Workers орчинтой яг ижил байдлаар туршихдаа:

```bash
bun run preview                 # build + локал workerd (http://localhost:8787)
```

Локал дээр Turnstile болон Google Sheets-ийн түлхүүр шаардлагагүй: Turnstile туршилтын түлхүүр
ашиглана (`.dev.vars` → `NEXTJS_ENV=development`), Sheets sync-ийг чимээгүй алгасна. Production
дээр Turnstile secret байхгүй бол маягтууд татгалзана (spam-аас хамгаалах үүднээс).

## Production (Cloudflare Workers)

Сайт **https://unicef-club-130.erkhes-labs.workers.dev** дээр ажиллаж байна. Deploy нь **гараар**
хийгддэг (CI / автомат deploy байхгүй). Бүх командыг төслийн хавтаснаас ажиллуулна; эхлээд
`bunx wrangler whoami`-аар зөв Cloudflare бүртгэлд нэвтэрсэн эсэхээ шалгана.

| Нөөц              | Нэр                                       |
| ----------------- | ----------------------------------------- |
| Worker            | `unicef-club-130`                         |
| D1 (APAC)         | `unicef-club-130-db` (binding `DB`)       |
| R2 — зураг        | `unicef-club-130-media` (binding `MEDIA`) |
| R2 — OpenNext кэш | `unicef-club-130-opennext-cache`          |

Анхны тохиргооны алхмууд: [DEPLOY_CHECKLIST.md](./DEPLOY_CHECKLIST.md).

### Дахин deploy хийх

```bash
git pull
bun install
bun run check && bun run build
bun run db:migrate:remote     # шинэ migration байвал (доорхыг үз)
bun run deploy                # build + Cloudflare руу гаргана
```

### Шинэ migration ажиллуулах

1. `src/db/schema.ts`-г өөрчилнө → `bun run db:generate` (шинэ файл `drizzle/migrations/`-д).
2. Локал дээр шалгана: `bun run db:migrate:local` → `bun run dev`.
3. Production: `bunx wrangler d1 migrations list DB --remote` (юу ажиллахыг харна) →
   `bun run db:migrate:remote`.
4. Шинэ кодыг `bun run deploy`. Багана устгах/нэр солих migration-ийг deploy-оос **өмнө** биш,
   хуучин код ашиглахаа больсны дараа ажиллуулна.

⚠️ `bun run db:seed:local` / `scripts/seed.ts` нь жишээ контент — production дээр **ажиллуулахгүй**.

### Нууц утга (secret) нэмэх / солих

Secret-ийг хэзээ ч файлд, git-д, чатад бичихгүй. Утгыг терминал дээр нууцаар асууна:

```bash
bunx wrangler secret list                          # ямар secret байгааг харах (утга харагдахгүй)
bunx wrangler secret put CLERK_SECRET_KEY          # утгыг асууна, оруулахад шууд хүчинтэй
bunx wrangler secret delete <НЭР>
```

| Нэр                                  | Заавал | Тайлбар                                                  |
| ------------------------------------ | ------ | -------------------------------------------------------- |
| `CLERK_SECRET_KEY`                   | Тийм   | Clerk production instance → API keys → Secret key        |
| `CLERK_WEBHOOK_SIGNING_SECRET`       | Тийм   | Clerk → Webhooks → endpoint → Signing secret (`whsec_…`) |
| `TURNSTILE_SECRET_KEY`               | Тийм   | Холбоо барих маягтын Turnstile widget-ийн secret key     |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL`       | Үгүй   | Google Sheets sync (бүгд байхгүй бол sync алгасагдана)   |
| `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` | Үгүй   | Service account JSON-ийн `private_key`                   |
| `GOOGLE_SHEET_ID`                    | Үгүй   | Sheet URL-ийн `/d/<ID>/` хэсэг                           |

Нууц биш тохиргоо (`SITE_URL`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `TURNSTILE_SITE_KEY`,
`GOOGLE_SHEET_TAB`) нь `wrangler.jsonc` → `"vars"`-д байна; өөрчилсний дараа `bun run deploy`.

### Clerk тохиргоо (нэвтрэлт)

Нэвтрэлтийг [Clerk](https://dashboard.clerk.com) хариуцна: **Google** эсвэл **и-мэйлд ирэх нэг
удаагийн код**, нууц үг байхгүй. Нэвтрэх, бүртгүүлэх нь нэг дэлгэц (`/sign-in`); анх нэвтрэхэд
бүртгэл автоматаар үүснэ.

Clerk dashboard дээрх тохиргоо (Development ба Production instance хоёуланд):

1. **User & authentication**: Email → «Email verification code» (бүртгүүлэх, нэвтрэх); Password
   OFF; Phone, Username OFF; First/Last name OFF; «Allow users to delete their accounts» OFF
   (бүртгэл устгах нь сайтын «Бүртгэлээ устгах» товчоор явна — D1-ийн өгөгдлийг цэвэрлэдэг).
2. **SSO connections → Google** ON (production дээр өөрийн Google OAuth credential).
3. **Sessions → Customize session token**: `{ "role": "{{user.public_metadata.role}}" }`.
4. **Webhooks**: `https://<домэйн>/api/webhooks/clerk`, events `user.created`, `user.updated`,
   `user.deleted`. Signing secret → `CLERK_WEBHOOK_SIGNING_SECRET`.
5. **API keys**: Publishable key → `wrangler.jsonc` vars (production) / `.dev.vars` (локал);
   Secret key → `wrangler secret put CLERK_SECRET_KEY` / `.dev.vars`.

Локал дээр webhook заавал биш: хэрэглэгч анх нэвтрэхэд сайт өөрөө Clerk-ээс уншиж D1-д бичнэ.

### Анхны админ

1. Сайтад **нэг удаа** өөрийн Google / и-мэйлээр нэвтэрнэ (Clerk бүртгэл үүснэ; эрхгүй тул
   «Гишүүн болох» хуудас руу орно).
2. Өөрийн терминалд:

```bash
bun run admin:grant -- <таны-и-мэйл>      # Clerk production Secret key-г нуугдмал асууна
```

3. 1 минутын дотор (эсвэл гараад дахин нэвтрэхэд) «Нэвтрэх»-ийн дараа `/admin` руу орно. Бусад
   админыг **Админ → Хэрэглэгчид**-ээс «Админ болгох» товчоор нэмнэ.

### Бүх админ нэвтэрч чадахгүй болсон үед (break-glass)

- Админ эрх алдагдсан / хэн ч админгүй болсон: `bun run admin:grant -- <и-мэйл>` — эрх олгохоос
  гадна идэвхгүй (ban) болсон бүртгэлийг идэвхжүүлнэ. Clerk Secret key хэрэгтэй (Clerk dashboard
  → API keys) тул Clerk бүртгэлд хандах эрхтэй хүн л хийж чадна.
- Google / и-мэйл рүүгээ нэвтэрч чадахгүй: Clerk dashboard → **Users** → тухайн хэрэглэгч →
  и-мэйл хаяг нэмэх/солих, эсвэл шинэ хүнээр нэвтрүүлээд `admin:grant`.
- Clerk dashboard-ийн бүртгэлээ 2 шатлалт баталгаажуулалттай байлгаж, хамгийн багадаа 2 хүн
  (клубын удирдагч + хариуцсан багш) хандах эрхтэй байх ёстой.
- `bun run admin:revoke -- <и-мэйл>` нь сүүлчийн идэвхтэй админыг хасахаас татгалзана.

### Жилийн тайлан оруулах (гишүүд, үйл ажиллагаа, үр дүн)

Тайлангийн түүхий өгөгдөл (гишүүдийн нэр, цаг) **хувийн** тул `private/` хавтсанд хадгалагдана
(`.gitignore`-д орсон, GitHub руу орохгүй). Жишээ: `private/report-2025-2026.json`.

```bash
bun run report:seed                    # private/seed-report-<он>.sql үүсгэнэ (+ тоонуудыг шалгана)
bun run report:seed -- --local         # ...мөн локал D1-д оруулна
bunx wrangler d1 execute DB --remote --file private/seed-report-2025-2026.sql   # production
```

- Дахин ажиллуулахад давхардахгүй. Гишүүд, мэдээ, арга хэмжээ байвал **хөндөхгүй** (админы засвар,
  зураг, зөвшөөрөл хадгалагдана). Үр дүнгийн тоо болон тайлангийн тохиргоо (клубын мэдээлэл, тоон
  үзүүлэлт, хамтрагчид, «Бидний тухай») тайлангийн утгаар **дарагдана**.
- Идэвхтэй гишүүдийн нэр анхнаасаа **нийтэд харагдахгүй**. Зөвшөөрөл авсны дараа Админ → Гишүүд →
  сонгоод «Нэрийг нийтэд харуулах». Хувь хүний сайн дурын цаг сайт дээр хэзээ ч харагдахгүй.
- Дараагийн жилийн тайлан: шинэ JSON (`private/report-2026-2027.json`) → `bun run report:seed --
--file private/report-2026-2027.json`. Эсвэл Админ → **Жилийн үр дүн**-ээс гараар нэмнэ.


Эсвэл Cloudflare Dashboard → **Workers & Pages → unicef-club-130 → Observability / Logs**.

### Custom домэйн холбох (дараа нь)

Домэйн Cloudflare дээр DNS-тэй (zone) байх ёстой.

1. Dashboard → **Workers & Pages → unicef-club-130 → Settings → Domains & Routes → Add → Custom

   `"routes"` мөрийн тайлбарыг авч домэйноо бичнэ.
2. `wrangler.jsonc` → `"vars"`: `SITE_URL`-ийг шинэ домэйн болгоно. Clerk production instance-ийн

3. Dashboard → **Turnstile** → widget → **Hostname management**-д шинэ домэйнийг нэмнэ.
4. `bun run deploy`. Дараа нь workers.dev URL-ийг хаах бол: Settings → Domains & Routes →
   `workers.dev` → Disable.

## Админ хэсгийг ашиглах

Нэвтрэх: сайтын дээд талын **«Нэвтрэх»** товч (эсвэл `/sign-in`). Нэвтэрсний дараа эрхээрээ
шилжинэ: админ → `/admin`, гишүүн → `/me`, эрхгүй (өргөдөл гаргагч) → `/join`. Аватар цэсэнд
**Админ** (админд), **Миний хэсэг** (гишүүн, админд), **Өргөдөл** (өргөдөл гаргагчид), **Гарах**.

| Эрх                          | Боломж                                                                   |
| ---------------------------- | ------------------------------------------------------------------------ |
| **Админ**                    | Админ хэсэг бүхэлдээ (клубын удирдагчид, хариуцсан багш) + «Миний хэсэг» |
| **Гишүүн**                   | «Миний хэсэг» (`/me`): профайл, сайн дурын цаг, арга хэмжээнд бүртгүүлэх |
| **Эрхгүй (өргөдөл гаргагч)** | Нээлттэй элсэлтэд өргөдөл гаргах, өөрийн өргөдлийн төлөвийг харах        |

Эрх нь Clerk-ийн `publicMetadata.role`-д хадгалагдаж, D1 `users` хүснэгтэд хуулбарлагдана.
`/admin/*`, `/me/*`-ийг middleware шалгаад, хуудас болон үйлдэл бүр сервер талд дахин шалгана
(`src/lib/auth/session.ts`: `requireAdmin()`, `assertAdmin()`, `assertMember()`).

### Хэрэглэгчид (Админ → Хэрэглэгчид)

- Сайтад нэвтэрсэн **бүх хүн** (өргөдөл гаргагч, гишүүн, админ): хайх, төрлөөр шүүх, өргөдлийн
  төлөв, бүртгүүлсэн огноо.
- **Админ болгох / Гишүүн болгох / Эрх хасах**.
- **Идэвхгүй болгох** (Clerk ban): нэвтэрч чадахгүй, мэдээлэл хадгалагдана, буцаан
  **Идэвхжүүлэх** боломжтой. Клубээс гарсан удирдагчид үүнийг хэрэглэнэ.
- **Бүр мөсөн устгах**: и-мэйлийг дахин бичиж баталгаажуулна. Clerk бүртгэл устаж, өргөдөл болон
  хувийн мэдээлэл D1-ээс устна; гишүүний мөр «Устгагдсан гишүүн» болж нэргүйждэг — сайн дурын цаг
  нь нийт дүнд үлдэнэ.
- **Гишүүнтэй холбох**: Гишүүд хэсэгт и-мэйл бичсэн (жишээ нь тайлангаас оруулсан) гишүүн тэр
  и-мэйлээр нэвтэрвэл товч гарна. Автоматаар хэзээ ч холбохгүй.
- Хамгаалалт: админ өөрийгөө хасах/идэвхгүй болгох/устгах боломжгүй; **сүүлчийн админыг** хасах,
  идэвхгүй болгох, устгах боломжгүй.

### 2 шатлалт баталгаажуулалт (2FA)

Clerk dashboard дээр **Multi-factor → Authenticator application** асаалттай бол хэрэглэгч бүр
аватар цэс → «Бүртгэлийн тохиргоо» → «Аюулгүй байдал»-аас өөрөө асаана. Хэрэглэгчдийн
жагсаалтад 2FA асаагаагүй админ «2FA асаагаагүй» гэж тэмдэглэгдэнэ. (Clerk-ийн үнийн төлөвлөгөөнөөс
шалтгаалан production-д MFA байхгүй байж болно — DEPLOY_CHECKLIST.)

### Ажлыг хурдасгах

- **⌘K / Ctrl+K**: хэсэг рүү шилжих, «Шинэ мэдээ» гэх мэт үйлдэл, мэдээ / арга хэмжээ / цомог /
  гишүүн / хэрэглэгчийг нэрээр хайх.
- **⌘S / Ctrl+S**: нээлттэй засварын маягтыг хадгална. Хадгалаагүй өөрчлөлттэй хуудаснаас гарахад
  сануулна.
- **Мэдээ**: «Онцлох» (нүүр хуудсанд эхэнд), SEO гарчиг/тайлбар, доор нь харуулах зургийн цомог,
  «Урьдчилан харах» (ноорог, товлосон мэдээ). Ирээдүйн огноотой нийтэлсэн мэдээ тэр мөчөөс харагдана.
- **Цомог → Арга хэмжээ**: цомгийг арга хэмжээтэй холбоход хоёр хуудас бие биедээ холбоос гаргана.
- **Түгээмэл асуулт** (`/faq`): Админ → Түгээмэл асуулт.
- **Системийн төлөв**: D1, R2, Clerk, webhook, Turnstile, Sheets-ийн төлөв; контентын JSON экспорт.

### Нөөц ба сэргээх (D1)

```bash
bunx wrangler d1 export DB --remote --output backup-YYYY-MM-DD.sql   # бүрэн нөөц (git-д оруулахгүй)
bunx wrangler d1 time-travel info DB                                  # сэргээх цэгүүд (30 хоног)
bunx wrangler d1 time-travel restore DB --timestamp=2026-11-20T10:00:00+08:00
```

`restore` нь бүх өгөгдлийн санг тэр мөч рүү буцаана (дараах өөрчлөлтүүд алга болно) — эхлээд
`export` хийнэ.

### Үйлдлийн түүх (audit log)

**Админ → Үйлдлийн түүх**: админ хэсэгт хийгдсэн өөрчлөлт бүр (хэн, юуг, хэзээ, өмнөх → шинэ утга),
хэрэглэгч/төрөл/огноогоор шүүнэ. Өргөдөл гаргагчийн нэр түүхэнд бичигдэхгүй (зөвхөн дугаар);
өргөдөл устгахад түүнтэй холбоотой бичлэгүүд хамт устна.

### Сайтын тохиргоо ба «Бидний тухай» хуудас

Сайт дээр **зохиомол мэдээлэл гарахгүй**: бөглөөгүй талбар, хоосон жагсаалт бүхий хэсэг харагдахгүй.
Англи талбар хоосон бол `/en` дээр монгол текст гарна.

- **Админ → Сайтын тохиргоо** (зөвхөн админ): клубын нэр/танилцуулга/он, лого ба нүүр зураг,
  холбоо барих (хаяг, и-мэйл, утас, цагийн хуваарь, газрын зураг — embed хаяг эсвэл
  өргөрөг/уртраг), сошиал хаягууд, нүүр хуудасны тоон үзүүлэлт (гараар эсвэл D1-ээс автоматаар
  тоолох), хамтрагчид (нэр, лого, холбоос, дараалал), хандивын мэдээлэл, гишүүнчлэлийн маягтын
  сонголтууд.
- **Админ → Бидний тухай хуудас**: танилцуулга, түүх, эрхэм зорилго, үнэт зүйлс, хийдэг ажлууд.
  «Түүх» ба «Хийдэг ажил» нь ноорог текст — шалгаж засаад «Сайт дээр харуулах»-г чагтлах хүртэл
  нийтэд харагдахгүй. Удирдлагын хэсэг нь Гишүүд → «Удирдлага» бүлгээс автоматаар гарна.

### Мэдээ нэмэх

1. Админ → **Мэдээ** → "Шинэ мэдээ".
2. Гарчиг, товч агуулга, ангилал, агуулга (засварлагч дээр тод, жагсаалт, холбоос гэх мэт).
3. Slug хоосон бол гарчгаас автоматаар үүснэ (жишээ: «Хүүхдийн эрх» → `khuukhdiin-erkh`).
4. **Нүүр зураг** → "Зураг сонгох" (автоматаар багасгаж, GPS мэдээллийг арилгана).
5. Англи хувилбар заавал биш — хоосон бол `/en` дээр монгол текст харагдана.
6. Төлөв: **Ноорог** (зөвхөн админд) эсвэл **Нийтлэгдсэн**. Ирээдүйн огноо тавьвал тэр цагаас
   харагдана.

Арга хэмжээ, гишүүд, зургийн цомог ижил зарчмаар ажиллана. Зургийн цомогт олон зураг зэрэг
нэмж, дараалал солих, нүүр зураг сонгох боломжтой.

### Элсэлт зарлах (Админ → Элсэлт)

«Гишүүн болох» (`/join`) хуудас **зөвхөн элсэлт нээлттэй үед** маягттай. Элсэлт үүсгээгүй эсвэл
хаагдсан бол «Элсэлт одоогоор хаалттай» гэж харагдана; дараагийн элсэлт товлогдсон бол түүний нэр,
нээгдэх огноо, тоолуур гарна. Нээгдэх, хаагдах мөчид нээлттэй байгаа хуудас өөрөө шинэчлэгдэнэ.

1. **Админ → Элсэлт → «Шинэ элсэлт»**.
2. Нэр, хичээлийн жил (`2026-2027`), нээгдэх ба хаагдах цаг (**Улаанбаатарын цагаар**).
3. **Ангиуд** — товчоор үүсгэнэ (жишээ: «9–12 анги, а–г») эсвэл зайгаар тусгаарлаж бичнэ.
   Хоосон бол сурагч ангиа өөрөө бичнэ.
4. **Нэмэлт асуулт** (10 хүртэл). «Нэгийг сонгох» төрөлд мөр бүрт нэг сонголт, англи хувилбарыг
   `|`-ийн ард: `Найзаасаа | From a friend`. Насанд хүрээгүй сурагчдаас хэрэгтэй зүйлийг л асууна.
5. **Багтаамж** (хоосон = хязгааргүй) ба дүүрэхэд: «Хүлээлгийн жагсаалтад бүртгэх» эсвэл
   «Өргөдөл авахаа зогсоох». Спам ба татгалзсан өргөдөл тоонд орохгүй.
6. Нэг үед зөвхөн нэг элсэлт байна — хугацаа давхцвал хадгалахгүй.

Элсэлт нээлттэй үед сайтын дээд талд «Элсэлт нээлттэй — … хүртэл!» тууз автоматаар гарна
(элсэлт дээр унтрааж болно; орон дүүрч хаагдсан бол гарахгүй). **Сайтын тохиргоо → Зарлалын
тууз**-ыг асаавал тэр зарлал автомат туузын **оронд** гарна.

### Өргөдөл гаргах (нэвтэрсний дараа)

1. Сурагч «Гишүүн болох» → **«Нэвтэрч өргөдөл гаргах»** → Google эсвэл и-мэйл кодоор нэвтэрнэ.
2. Маягт: овог нэр (кирилл), анги (элсэлтийн жагсаалтаас), утас (8 орон, 6/7/8/9-өөр эхэлсэн),
   яагаад элсэх, хэрхэн туслах, элсэлтийн нэмэлт асуулт, зөвшөөрөл. И-мэйлийг бүртгэлээс авна.
3. Нэг бүртгэлээр **нэг элсэлтэд нэг өргөдөл**. Илгээсний дараа `/join` дээр төлөв харагдана:
   **Хүлээгдэж байна / Тэнцсэн / Тэнцээгүй / Хүлээлгийн жагсаалт** + админы мессеж (байвал).
4. Бүртгэл тус бүр 10 минутад 5 удаа илгээх оролдлоготой. Бүртгүүлэх үеийн бот хамгаалалтыг Clerk
   хийнэ (Turnstile нь зөвхөн «Холбоо барих» маягтад үлдсэн).

### Өргөдлүүд (Админ → Өргөдлүүд)

- **Төлөв**: Шинэ → Хянаж байна → Ярилцлага → Тэнцсэн / Тэнцээгүй / Хүлээлгийн жагсаалт.
  Өргөдөл гаргагчид «Шинэ, Хянаж байна, Ярилцлага» нь «Хүлээгдэж байна» гэж харагдана.
- **Тэнцсэн** болгоход: бүртгэлд **гишүүн** эрх олгогдож, **Гишүүд** хэсэгт нийтэд харагдахгүй мөр
  үүснэ (эсвэл холбогдсон мөр идэвхжинэ). Дараагийн нэвтрэлтээр `/me` руу орно.
- **Тэнцээгүй**: «Энэ удаагийн элсэлтэд тэнцээгүй» + мессеж. Бүртгэл устахгүй; дараагийн элсэлт
  нээгдэхэд дахин өргөдөл гаргаж болно. Шийдвэрийг дараа нь өөрчилж болно (Тэнцсэн болговол эрх
  олгоно; Тэнцсэнээс өөр болговол гишүүн эрхийг буцаана — админы эрх хэвээр).
- **Өргөдөл гаргагчид харагдах мессеж** ба **дотоод тэмдэглэл** (зөвхөн админд) тусдаа.
- **Дахин өргөдөл гаргахыг хориглох**: зүй бусаар ашигласан бүртгэлд (буцааж цуцалж болно).
- **Шүүх, хайх** (нэр / утас / и-мэйл), олноор нь төлөв солих, **CSV татах**, устгах.
- Тэнцээгүй өргөдлийн хувийн мэдээллийг элсэлт хаагдсанаас хойш **N хоногийн дараа** (Сайтын
  тохиргоо → Гишүүнчлэл ба нууцлал, анхдагч 90) өдөр бүр автоматаар устгана (Worker cron).
- Нэвтрэлт шаардахаас өмнөх өргөдлүүд «хуучин (бүртгэлгүй)» гэж тэмдэглэгдэнэ.

### Сайн дурын цаг ба ирц

- **Арга хэмжээ → засах → «Сайн дурын бүртгэл»**: гишүүдэд бүртгэл нээх, орон тоо, хаагдах
  хугацаа. Нийтийн хуудсанд «Сайн дурын бүртгэл нээлттэй · N орон үлдсэн» гарна (нэр харагдахгүй).
- **Арга хэмжээ → «Сайн дурынхан»**: бүртгүүлсэн гишүүд; «Ирсэн» (цаг — арга хэмжээний
  үргэлжлэх хугацаагаар санал болгоно), «Ирээгүй», эсвэл «Бүртгүүлсэн бүгдийг Ирсэн болгох».
  Ирсэн гэж тэмдэглэхэд цаг **Сайн дурын цаг**-т автоматаар орно.
- **Админ → Сайн дурын цаг**: хичээлийн жил, багаар шүүх; гишүүн бүрийн нийт (тайлангаас +
  бүртгэсэн), «идэвхтэй» тэмдэг; сонгосон гишүүдэд цаг нэмэх; бичлэг устгах; **CSV (тайланд)**.
- Хувь хүний цаг сайт дээр хэзээ ч харагдахгүй. «Идэвхтэй гишүүд» (`/members`) нь зөвхөн босгод
  хүрсэн, нэрээ харуулахыг зөвшөөрсөн гишүүдийн нэрийг харуулна (Сайтын тохиргоо → Гишүүнчлэл ба
  нууцлал → «Идэвхтэй гишүүний жилийн цаг»).
- Багууд: Гишүүд → засах → «Баг» (бичсэн нэрс санал болгогдоно); Гишүүд хэсэгт багаар шүүнэ.

### Гишүүний хэсэг (`/me`)

- Профайл: нэр, анги (гишүүн өөрөө шинэчилнэ), баг, гишүүн болсон жил.
- Сайн дурын цаг: энэ хичээлийн жилийн нийт, өмнөх жилүүд, түүх, «идэвхтэй гишүүний босго»
  (Сайтын тохиргоонд цаг оруулсан бол явцын мөр).
- Ойрын арга хэмжээ: админ арга хэмжээн дээр «Гишүүдэд бүртгэл нээх»-ийг асаасан бол бүртгүүлнэ
  (орон дүүрвэл хүлээлгийн жагсаалт; хэн нэг нь цуцалбал дарааллаар орно).
- **Оролцооны гэрчилгээ** (`/me/certificate`): цагтай жил бүрт хэвлэх / PDF болгох.
- **Бүртгэлээ устгах**: «УСТГАХ» гэж бичиж баталгаажуулна (админ өөрийгөө устгаж чадахгүй).

### Зурвас

- **Зурвасууд**: «Холбоо барих» маягтаар ирсэн захидлууд, уншсан/уншаагүй (нэг сүлжээнээс 10
  минутад 3 зурвас).

## Хувийн мэдээллийн хамгаалалт (заавал уншина)

Сайтын хэрэглэгчдийн ихэнх нь **насанд хүрээгүй сурагчид**.

- Clerk-д зөвхөн и-мэйл (Google-ээр орвол нэр, зураг) хадгалагдана. Маягт зөвхөн шаардлагатай
  мэдээллийг авна (нэр, анги, утас, шалтгаан, туслах чиглэл, зөвшөөрөл).
- Гишүүний нэр, зургийг **зөвхөн эцэг эх/асран хамгаалагчийн зөвшөөрөлтэй** сайт дээр харуулна.
- Тэнцээгүй өргөдлийг хугацаа дуусахад автоматаар устгана; бүртгэл устгахад хувийн мэдээлэл
  устаж, сайн дурын цаг нэргүйгээр үлдэнэ. Үйлдлийн түүхэнд өргөдөл гаргагчийн нэр бичигдэхгүй.
- CSV файлыг хуваалцахдаа болгоомжтой байна.
- Secret, `.dev.vars`, service account JSON-ийг **хэзээ ч** git-д оруулахгүй, чатаар илгээхгүй.

7. ☐ Энэ README болон DEPLOY_CHECKLIST.md-ийг хамт уншиж, туршилтаар мэдээ нэмж үзнэ.

## Аюулгүй байдлын тохиргоо (товч)

- **Header-үүд** (`src/middleware.ts`, `src/lib/security-headers.ts`): хүсэлт бүрд шинэ nonce-тэй
  Content-Security-Policy (өөрийн script + Clerk-ийн Frontend API, Clerk bot хамгаалалт,
  Cloudflare Turnstile; iframe-д Turnstile ба Google Maps), HSTS, `frame-ancestors 'none'`,
  Referrer-Policy, Permissions-Policy, nosniff.
  Шинэ гадны үйлчилгээ (жишээ нь analytics, видео embed) нэмэх бол CSP-д зөвшөөрөл нэмнэ.
- **Нэвтрэлт**: Clerk (нууц үггүй). Middleware + хуудас/үйлдэл бүрт эрх шалгана; webhook-ийн
  Svix гарын үсгийг шалгана; эрх солигдоход D1 шууд шинэчлэгдэнэ.
- **Маягтууд**: «Холбоо барих» — Turnstile (production-д тест түлхүүр хүлээн авахгүй); өргөдөл —
  нэвтрэлт + бүртгэл тус бүрийн хязгаар.

## Засвар үйлчилгээ

- **Лого солих**: Админ → **Сайтын тохиргоо → Лого ба нүүр зураг**-аас upload хийнэ (R2, deploy
  хэрэггүй). Эсвэл `public/logos/school-130.png`, `public/logos/unicef.png` файлыг нэмээд
  `bun run brand:assets` → `bun run deploy`. Аль нь ч байхгүй үед "130" тэмдэг харагдана.
- **Өнгө солих**: `src/app/globals.css` → "BRAND PALETTE" хэсэг (бүх өнгө нэг дор).
- **Фонт**: Montserrat (гарчиг) ба Nunito Sans (текст) — сайт өөрөө өгдөг, Латин + Монгол кирилл
  (Ө, Ү) үсгээр багасгасан хоёр жижиг файл (`src/assets/fonts/`, OFL лиценз). Шинэчлэх бол
  `bun run fonts` → build.
- **Хөдөлгөөн (animation)**: гүйлгэхэд гарч ирэх (`reveal`, `reveal-group` класс), тоо тоолох
  (`CountUp`), хуудас солигдох fade, мэдээний зураг "шилжих" (View Transitions). Төхөөрөмж дээр
